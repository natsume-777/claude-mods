# ボードを使う

ボードは、会話のログに流れてしまう情報を、画面の右のパネルに残しておく作業メモです。Claude が書き込み、人は基本的に見るだけです。ボードには名前があり、セッションには属しません。セッションは 1 つのボードにつないで使い、新しいセッションはどのボードにもつながっていません。入力欄の上の帯に「ホワイトボード N件」と出ます（N が 0 ならカードはありません。「ボードを選ぶ」と出ているときは、まだどのボードにもつながっていません）。帯やパネルでは「ホワイトボード」と出るので、利用者がそう呼んだときも、このボードへの頼みとして扱います。

## ツール

| ツール | 入力 | すること |
| --- | --- | --- |
| `mcp__whiteboard__open_board` | `name` | その名前のボードにこのセッションをつなぐ。同じ名前のボードがあれば（このプロジェクトのものを優先、大文字小文字・全角半角は区別しない）それにつなぎ、無ければ作る。名前は 40 文字まで |
| `mcp__whiteboard__list_boards` | 省略できる `all` | ボードの一覧。このプロジェクトのボードを新しい順に、名前・最後の書き込み・枚数・最後に書いたセッションの題・カードの題で返す。つないでいるボードに印が付く。`all: true` で、ほかのプロジェクトのボードと古いボードも |
| `mcp__whiteboard__rename_board` | `name` | つないでいるボードの名前を変える。このプロジェクトのほかのボードと同じ名前にはできない |
| `mcp__whiteboard__set_card` | `id`, `title`, `body`, `pin` と `style`（省略できる） | カードを追加する。同じ `id` があれば上書きする（表示の位置は変わらない）。`pin: true` で固定、`pin: false` で固定を外す、省略すると今のまま。`style` は色（下の「カードの色」）、省略すると今のまま |
| `mcp__whiteboard__edit_card` | `id`, `find`, `replace`, `all`, `style`（`id` 以外は省略できる） | 本文の一部だけを書き換える。本文の中の `find`（改行を含んでよい）を `replace` に置き換える。一致がちょうど 1 箇所のときだけ置き換え、0 箇所なら見つからなかったと断られ、2 箇所以上なら断られる（`all: true` で全部を置き換える。または前後を含めて一意な `find` にする）。`replace` が空なら消す。title・固定・位置は変わらない。`id` と `style` だけなら色だけを変える。`find` も `style` もないと断られる |
| `mcp__whiteboard__append_card` | `id`, `text` | 本文の末尾に `text` を足す（本文が空でなければ改行 1 つを挟む）。title・固定・位置は変わらない |
| `mcp__whiteboard__remove_card` | `id` | カードを 1 枚消す。無い `id` なら、その旨が返る |
| `mcp__whiteboard__clear` | なし | カードを全部消す |
| `mcp__whiteboard__list_cards` | 省略できる `titles_only`・`id`・`query`・`since` | ボードを読む。結果の 1 行目は `rev: N`（ボードの版）。引数なしは全カードの `id`・`title`・`body` を全文で返す。`titles_only: true` は目次（`id`・`title`・`chars`、チェックリストのあるカードは `tasks`）、`id` はそのカード 1 枚（ほかの引数より優先）、`query` は語をすべて含むカードと一致した行を返す。`since` に前に読んだ rev を渡すと、その後に変わったカードだけと、今ある全カードの `ids:` の行を返す（`titles_only`・`query` はその中で効く）。パネルと同じ順（固定が先）で、固定のカードには `pinned: true`、色のあるカードには `style` が付く |
| `mcp__whiteboard__undo_card` | `id` | カードの最後の書き換えを 1 つ戻す。書き換えたカードは `title`・`body`・固定・色が 1 つ前の版に戻る（位置は変わらない）。戻せるのは 1 段だけで、続けてもう一度呼ぶと戻す前の版にやり直す。`remove_card`・`clear` で消したカードは、最近消した 5 枚まで末尾に戻せる（カードが上限の枚数あるときは断られる）。消したカードを戻した直後にもう一度呼ぶと、そのカードはまた消える（やり直し）。前の版がなければ、その旨が返る |

カードのツール（`set_card` から `undo_card` まで）は、つないでいるボードが相手です。どのボードにもつないでいないと、すべて断られます。

上限は、1 つのボードにカード 20 枚（既定。利用者の設定で 5〜40 枚に変わっていることがあり、いっぱいのときのツールのエラーに今の上限が書かれる）、`title` 60 文字、`body` 4000 文字、`id` は英数字と `_` `-` の 40 文字までです。超えるとツールがエラーを返すので、短くするか、済んだカードを消してからやり直します。

## 利用者の頼み方ごとの動き

- 「ボードにこれを書いて」「残しておいて」: 内容に合う `id` で `set_card` する。すでに同じ話題のカードがあれば、同じ `id` で上書きして更新する。迷うときは先に `list_cards` で何があるかを見る
- 「ボードのあれを消して」: どのカードか分かるなら `remove_card`。曖昧なら `list_cards` で見て、利用者に確かめてから消す。全部と言われたときだけ `clear`
- 「さっきの書き換えを戻して」「消したカードを戻して」: どのカードか分かるなら、その `id` で `undo_card` を 1 回呼ぶ。分からなければ、利用者に確かめる。戻したあと、どの版に戻ったかを一言で伝える。自分がカードを間違えて上書き・編集したと気づいたときも、`undo_card` で戻してから書き直す。2 回続けて呼ぶと元に戻る（やり直し）ので、戻しすぎない
- 「ボードを整理して」: `list_cards` で全部読み、済んだもの・古いものを `remove_card` で消し、重なる話題は 1 枚にまとめて `set_card` で書き直す。何を消して何をまとめたかを、最後に一言で伝える
- 「ボードに何が書いてある？」: `list_cards` の `titles_only: true` で目次を見て、要点だけ答える。内容をそのまま貼り直さない
- `titles_only` の結果に `stale: true`（しばらく書き換えのないカード）があり、そのカードの作業がもう済んでいるように見えるときは、消すか、ほかのカードにまとめるかを利用者に提案する。消す前に必ず確かめ、自分の判断だけで消さない
- 「◯◯のボードを使って」「◯◯のボードを作って」: その名前で `open_board` を呼ぶ。同じ名前があればそれにつながり、無ければ作られる。返事にある枚数を一言伝える
- カードのツールが「まだどのボードにもつながっていません」で断られたとき: 利用者がボードの名前を言っていればその名前で `open_board`。言っていなければ `list_boards` で今あるボードを見て、作業に合うものがあれば利用者に確かめてからつなぎ、無ければ作業の内容が分かる短い名前（例: `whiteboard 開発`、`CI の修正`）で作る。どれにするか迷うときは利用者に聞く
- 名前の付け方: プロジェクトに 1 枚で足りるのか、話題ごとに分けるのかは利用者の使い方に合わせる。同じプロジェクトで話題が並ぶ（クライアント・サーバ・企画書など）なら、話題の名前にする
- 「前のセッションのボードはどこ？」「前に書いた URL は？」: `list_boards` で探し（ほかのプロジェクトや古いボードも見るなら `all: true`）、`open_board` でそのボードにつないでから `list_cards` で読む。つなぎ直すと、このセッションが書くボードも変わることを先に伝える
- 「ボードの名前を変えて」: `rename_board`。利用者はパネルのいちばん下の [名前を変える] でも変えられる
- 利用者がセッションを入れ替えるときの引き継ぎの文を書くときは、使っているボードの名前を「◯◯のボードを使って」の形で入れる。新しいセッションの Claude がそれで `open_board` を呼べる
- ツールが「ほかのセッションが同じボードを書き換えたので、書き込みませんでした」で断られたとき: 同じボードに、ほかのセッションもつながっている。`list_cards`（前の rev を `since` に渡すか `titles_only`）で読み直し、ほかのセッションの書き込みを消さないように書き直す
- 会話の圧縮のあと、要約の末尾に「（whiteboard）このセッションがつないでいるボード「◯◯」に N 枚のカードがあります」で始まる目次（`id: title` の一覧）が付いていることがある。続きの作業にカードの中身が要るときは、`list_cards` に `id` を渡して、そのカードだけ読む
- 一度読んだボードを読み直すとき: 前の結果の `rev` を覚えておき、`list_cards` に `since` でその rev を渡す。変わったカードだけが返り、`ids:` に無いカードは消されたもの。全部を読み直さない。圧縮のあとや rev が分からないときは、`titles_only: true` から読む
- 「ボードの手順 3 は？」のように内容を尋ねられたとき、「手順 3 を済みにして」のように指示されたとき: 先に `list_cards` の `query`（語を空白で分けて並べる）か `titles_only: true` で探し、必要なカードだけ `id` を指定して読む。引数なしの `list_cards` は全文を返すので重い。書き換えは、読んだカードの本文のうち変える行だけを `edit_card` の `find` と `replace` にして行う（「手順 3 を済みにして」なら、その行だけ書き換える）。末尾に足すだけなら `append_card`。全文を `set_card` で書き直さない（トークンがかかる）。`find` は、本文のその行を一字一句そのまま写し、1 箇所にしか一致しない長さにする

## カードの書き方

- `id` は短い英語の名前にする（`plan`、`urls`、`jobs`、`todo` など）。話題が変わらない限り同じ `id` を使い続けるので、後から見て分かる名前にする
- 1 カード 1 話題にする。手順、動いている処理、リンクは別のカードにする
- `title` は見出しとして一目で分かる短さにする
- `body` は Markdown で、要点だけを書く。手順は番号付きの箇条書き、状況は「何が・どうなっている」、リンクは `[名前](URL)` にする。図は、` ```mermaid ` の基本的な flowchart / graph（と、参加者と矢印だけの sequenceDiagram）なら、パネルで図になる。subgraph は枠で囲んで描かれるが、subgraph 自体に矢印を引く（`A --> sg1`）と図にならないので、矢印は中のノードに引く。それ以外の mermaid や ASCII の図は、コードブロックとして読める形で表示される（描画はされない）。関係や流れは、箇条書きや表でも伝わる
- 手順や ToDo は `- [ ]` / `- [x]` のチェックリストで書く。パネルのタイトルの下の行に進み具合（`3/5`）が出て、`list_cards` の `titles_only` にも `tasks` が付く。1 つ済ませたら、その行の `[ ]` を `[x]` にする `edit_card` だけでよい
- 状況が変わったら、同じ `id` のカードを更新する。一部だけ変わるなら `edit_card` か `append_card`、全体を書き直すなら `set_card`。更新のたびに新しいカードを増やさない
- `pin: true` は、人が常に見ていたいカード（今の手順の全体像、URL の一覧など）だけに使う。固定したカードはパネルの上に並ぶので、使いすぎると意味がなくなる。固定を外すときは `pin: false`。`pin` を省略して上書きすると、固定は今のまま
- 固定したカードの題は、入力欄の上の帯にも出ることがある（いちばん最近書き換えた 1 枚）。固定するカードの `title` は、本文なしでもそれだけで意味が通るように書く
- 用が済んだカードは消す。残すのは、これから先も見返すものだけにする
- 利用者の最後の依頼のあとで書き換えたカードには、パネルで「新規」「更新」と変わった行数が付く。ボードに書いた中身を、チャットでもう一度繰り返さなくてよい（どのカードを書いたかを一言添えれば足りる）

## カードの色

`style` に使える名前は `red`・`orange`・`yellow`・`green`・`blue`・`purple`・`gray` と、色を外す `none` だけです。色コードやほかの語は断られます。

- 色に決まった意味はない。「赤は問題」のような意味を自分で付けない
- 色を付けるのは、利用者に頼まれたとき（「deploy のカードは青で」）か、同じ話題のカードを同じ色にそろえるときだけ
- 利用者が会話で色の意味を決めたら（「止まっている作業は赤に」など）、それに従う
- 色だけを変えるときは、`edit_card` に `id` と `style` だけを渡す。本文を送り直さない

## 使いどころ

利用者に頼まれなくても、会話の中で流れ去ってしまう次のような情報は、ボードに残すと役に立ちます。ただし、会話にもう書いたことをただ写すためには使いません。

- 数回のやり取りにまたがる手順やチェックリスト
- 並行して動かしている処理（バックグラウンドのタスクなど）の今の状況
- このセッションで開く URL や、参照するファイルの場所
- 利用者と決めたこと
