# 利用枠の節約の監査

過去のセッションの記録（`~/.claude/projects/` の JSONL）をこの PC の中だけで集計し、消費を重くしている使い方を見つけて、直し方を伝えます。記録はどこにも送りません。会話の本文も出力しません。

扱うのは「節約」、つまり同じ仕事をより少ない消費で終えることだけです。作業の時間帯をずらす、リセット前に並列数を上げるといった、枠をどう使い切るかの話は扱いません。

判断の根拠は、同じフォルダの [reference.md](reference.md) にまとめてあります。所見を説明する前に読んでください。

## 1. 集計する

範囲を決めます。頼まれた範囲がなければ、今のプロジェクトの直近 7 日にします。

```bash
node "${CLAUDE_PLUGIN_ROOT}/scripts/audit.js" --since <7日前の YYYY-MM-DD> --json --top 10 > <一時ファイル>
```

- すべてのプロジェクトを見るなら `--all-projects`、特定のセッションなら `--session <id の先頭>`（くり返せる）
- 結果は一時ファイルに書き、`findings`、`total`、`byThreadKind`、`mainContext`、`agentTypes`、`skillListing` など必要な部分だけを読みます。全文を会話に入れません（reference.md の「大きな結果は文脈に入れない」）
- Node がない環境では動きません。そのときは、Node が要ることを伝えて止めます

## 2. 所見を選ぶ

`findings` は、見込みの節約量（`saving`）の大きい順に並んでいます。数字は比べるための目安なので、「消費のおよそ何 %」の形で伝えます。

上位から 2〜3 件を選びます。選ぶときは reference.md の「所見ごとの読み方」に従い、所見の `action` の文をそのまま処方にしません。とくに次の所見に気をつけます。

- `main-context`（メインの会話が大きい）: 新しいセッションや `/clear` を既定の処方にしません。何が文脈を大きくしているか（大きなツールの結果か、会話そのものか）を見て、入れない工夫を先に勧めます
- `main-idle`（キャッシュが切れたあとの再開）: 1 時間以上あけた再開が何度もあるセッションは、はっきり伝えます。ただし前の会話の経緯が要る場合は続けてもよい、と添えます
- `agent-tools`（エージェントのツールの許可）: `evidence` の最後の行で、そのエージェントがスキルを読み込んでいたかを見ます。読み込んでいたなら、`Skill` を外すのは検討として伝えます
- `skill-listing`（スキルの一覧）: 使われていないプラグインの名前とスキルの数を伝えます。所見の範囲で使われなかっただけなので、ほかの作業で使うプラグインでないかを利用者に聞きます

## 3. 伝える

利用者に合わせた、平易な言葉で書きます。最初に出すのは次の形です。

- 1 行目: いちばん効く直し方を 1 つ
- 所見ごとに 3 行まで: 何が起きているか（消費のおよそ何 % か）、なぜ重いのか、明日から何を変えるか
- 「警告」（多くの場合は直したほうがよい）と「検討」（品質や手間とのかね合いがある）を言い分ける

「重み」「TTL」「ephemeral」のような内部の言葉は、聞かれるまで前に出しません。詳しく聞かれたら、集計の数字と、reference.md の仕組みの説明を出します。

例:

> 同じセッションを、数時間あけて 4 回使い回しています。再開のたびに会話全体を読み込み直していて、このセッションの消費の約 8% がそのためです。数時間あけるときは、新しいセッションで始めるほうが軽くなります（前の会話の経緯が要るなら、続けても構いません）。

## 4. 直す（頼まれたときだけ）

エージェント定義の frontmatter に `experimental.cacheTtl: 1h` を足す、`tools` を絞る、使っていないプラグインをプロジェクトの設定で止めるといった、ファイルで直せる所見は、利用者が頼んだときに直します。

- 直す前に、どのファイルの何をどう変えるかを示し、了承をもらいます
- `model` の変更は品質に関わるので、提案にとどめ、利用者が選んだときだけ変えます
- エージェント定義を変えたら、セッションを開き直すまで反映されないことを伝えます
- 組み込みのエージェント（general-purpose、Explore、Plan など）の定義は変えられません。同じ役割の定義を自分で作る方法を案内します
- プラグインを止めるときは、まず `claude plugin list` でそのプラグインの正式な名前（`<プラグイン>@<マーケットプレイス>`）を確かめ、プロジェクトの `.claude/settings.json` の `enabledPlugins` に `"<プラグイン>@<マーケットプレイス>": false` を書きます。一覧に出ないプラグインは、ListPlugins ツール（claude.ai のアカウントで有効にしたプラグインの一覧）が使えるならそれで確かめます。そこにあるものは、claude.ai の設定で止めるよう利用者に伝え、アカウントの設定なのでほかのプロジェクトにも効くことを添えます。どちらにもないものは、名前だけを伝えます
